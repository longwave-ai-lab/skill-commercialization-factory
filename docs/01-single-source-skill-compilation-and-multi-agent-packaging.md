## 1. The Multi-Platform Fragmentation Crisis in AI Developer Tooling

Software engineers building custom rules, agentic skills, and verification workflows face a severe fragmentation problem across modern AI coding environments. Every major platform expects a different directory hierarchy, frontmatter schema, and context loading mechanism:

1. **Cursor IDE (`.cursor/rules/*.mdc`)**:
   - Expects individual `.mdc` files stored inside `.cursor/rules/` with YAML frontmatter declaring `description`, `globs`, and `alwaysApply`.
   - When an engineer places a plain `.md` file inside `.cursor/rules/` or omits the `globs` string, Cursor either fails to index the rule or loads it unpredictably across unrelated files.
2. **Claude Code CLI & Desktop (`CLAUDE.md` & `.claude/skills/*/SKILL.md`)**:
   - Expects a concise root constitution (`CLAUDE.md` at the repository root) paired with lazy-loaded domain skill folders under `.claude/skills/<skill-name>/SKILL.md`.
   - External security auditors such as **SkillsDirectory (`skillsdirectory.com`)** inspect the YAML frontmatter of `SKILL.md` for explicit `name`, `description`, and semantic `version: 1.0.0` fields before awarding a **Grade A (`100/100`)** trust badge.
3. **Google Antigravity (`GEMINI.md` & `.agents/skills/*/SKILL.md`)**:
   - Expects a root `GEMINI.md` instruction file alongside modular `.agents/skills/<skill-name>/SKILL.md` packages that agents load dynamically when task descriptions match the skill trigger.
4. **AI Search Crawlers & Developer CLI Workflows (`llms.txt` & `npx`)**:
   - Generative search crawlers (Perplexity, ChatGPT Search, Claude Web Search) look for `/llms.txt` at the repository root to map documentation structure without parsing HTML chrome.
   - Developers evaluating an open-source starter repository expect a single `npx @scope/<slug> init .` command rather than a ten-step manual copy-paste checklist.

When creators attempt to maintain these five target formats by hand, **version drift** is inevitable. A bug fix applied to `.cursor/rules/01-compiler.mdc` is forgotten in `.claude/skills/open-core-skill-compiler/SKILL.md`. Within three releases, the free GitHub repository contradicts the paid Gumroad bundle, and buyers encounter broken linters.

## 3. Automated Linter Extraction & Behavioral Fixture Verification

A recurring anti-pattern in commercial prompt packs is shipping unverified code snippets inside Markdown fences. Because Markdown code blocks are not executed by the author's editor, syntax typos, missing imports, and broken regular expressions go unnoticed until a paying customer tries to run the script.

During the `compile` stage, `factory.mjs` parses each module in `pro-bundle/rules/01..04.md`, locates the primary fenced `javascript` block under `## 3. Ready-to-Run Node.js Linter`, and writes the exact contents to `pro-bundle/scripts/<scriptName>` (and `github-repo/scripts/<scriptName>` for Module 01).

During the subsequent `audit` stage:
1. **AST Syntax Gate**: Each extracted `.mjs` file is validated via `node --check`.
2. **Adversarial Fail Fixture**: The audit engine creates an isolated temporary directory (`fs.mkdtempSync`), writes the module's `fixtures.fail.files` payload, executes the extracted linter, and verifies that it returns `exit code 1` while printing the expected diagnostic error code (`[COMPILER-001]`, `[GEO-001]`, `[HARNESS-002]`, `[DIST-001]`).
3. **Compliant Pass Fixture**: The audit engine creates a second isolated directory, writes `fixtures.pass.files`, executes the linter, and verifies that it returns `exit code 0`.

This two-way behavioral harness makes **Potemkin linters** (`process.exit(0)`) mathematically impossible to ship.

## 4. In-Memory POSIX ZIP Construction on Windows Hosts

When building commercial archives on Windows workstations, standard PowerShell `Compress-Archive` introduces two fatal flaws:
- It records Windows backslash path separators (`\cursor\rules\01.mdc`) inside the ZIP central directory, which causes `unzip` on macOS and Linux to create literal filenames containing backslashes instead of nested folders.
- It opens exclusive file locks on disk and fails intermittently when antivirus scanners or IDE indexers inspect the output file.

The Factory compiler solves both problems by constructing the entire ZIP archive inside a `.NET System.IO.MemoryStream` before touching the disk:
- Every relative path is normalized with `.Replace('\', '/')` and stripped of leading `./` prefixes.
- Every `.git` directory is filtered out before entry creation so internal commit logs and reflogs never leak into customer downloads.
- Every entry's `LastWriteTime` is pinned to a deterministic UTC timestamp (`2026-10-27T00:00:00Z`) for reproducible builds.
- The final byte array is flushed to disk inside a 10-attempt retry loop (`150ms` backoff), followed by a deep entry inspection that compares every archived file's uncompressed byte length against the source file on disk.

## 5. Tài Liệu Chuyên Khảo Tiếng Việt: Cơ Chế Biên Dịch Từ Một Nguồn Chuẩn & Đóng Gói Đa Nền Tảng

### 5.1. Bài Toán Phân Mảnh Định Dạng Giữa Các Công Cụ Lập Trình AI

Khi đóng gói bộ quy tắc AI thành sản phẩm thương mại, rào cản đầu tiên là mỗi công cụ lập trình đòi hỏi một cấu trúc thư mục và định dạng khai báo khác nhau:

1. **Cursor IDE (`.cursor/rules/*.mdc`)**:
   - Đòi hỏi các file có đuôi `.mdc` đặt trong thư mục `.cursor/rules/` kèm khối khai báo YAML ở đầu file gồm `description`, `globs` và `alwaysApply`.
   - Nếu người làm sản phẩm chỉ chép file `.md` thông thường vào hoặc quên khai báo đường dẫn `globs`, Cursor sẽ bỏ qua quy tắc đó hoặc nạp tràn lan gây tốn bộ nhớ.
2. **Claude Code CLI & Desktop (`CLAUDE.md` & `.claude/skills/*/SKILL.md`)**:
   - Đòi hỏi một file hiến pháp gốc ngắn gọn (`CLAUDE.md` dưới 200 dòng) đi kèm các thư mục kỹ năng chuyên biệt nạp chậm dưới `.claude/skills/<tên-kỹ-năng>/SKILL.md`.
   - Đặc biệt, hệ thống kiểm định bảo mật **SkillsDirectory (`skillsdirectory.com`)** bắt buộc đầu file `SKILL.md` phải khai báo đủ `name`, `description` và `version: 1.0.0` mới cấp chứng nhận **Hạng A (`100/100`)**.
3. **Google Antigravity (`GEMINI.md` & `.agents/skills/*/SKILL.md`)**:
   - Sử dụng file cấu hình gốc `GEMINI.md` kết hợp cùng hệ thống kỹ năng `.agents/skills/<tên-kỹ-năng>/SKILL.md` để tác tử tự động kích hoạt khi gặp nhiệm vụ tương ứng.
4. **Chỉ Mục Tìm Kiếm AI (`llms.txt`) & Bộ Cài Đặt Nhanh (`npx`)**:
   - Các công cụ tìm kiếm bằng AI (như Perplexity, ChatGPT Search) ưu tiên quét file `/llms.txt` ở thư mục gốc để lập chỉ mục tài liệu kỹ thuật.
   - Lập trình viên tải bản miễn phí trên GitHub luôn muốn gõ một lệnh `npx` duy nhất để chép toàn bộ cấu hình vào dự án trong vài giây thay vì phải tự tay tạo từng thư mục ẩn.

Nếu bạn mở từng nơi ra sửa thủ công mỗi khi cập nhật phiên bản, sự lệch lạc giữa các file chắc chắn sẽ xảy ra. Chỉ sau vài lần chỉnh sửa, bản miễn phí trên GitHub sẽ lệch hoàn toàn so với bản trả phí trên Gumroad, còn đoạn mã kiểm tra bên trong tài liệu thì bị lỗi cú pháp mà không ai phát hiện.

### 5.4. Cơ Chế Kiểm Thử Hai Chiều Cho Các Bộ Lọc Nhúng Trong Mô-Đun

Nhiều bộ quy tắc trên thị trường chỉ đính kèm đoạn mã minh họa trong tài liệu Markdown mà chưa từng chạy thử. Khi khách hàng chép đoạn mã đó ra file `.mjs` để chạy, trình biên dịch lập tức báo lỗi thiếu biến hoặc sai cú pháp.

Để khóa cứng chất lượng, `factory.mjs` kết hợp chặt chẽ hai bước:
- Trong bước biên dịch (`compile`), toàn bộ đoạn mã nằm dưới mục `## 3. Ready-to-Run Node.js Linter` của từng mô-đun được trích xuất thẳng ra file thực thi `scripts/lint_*.mjs`.
- Trong bước kiểm toán (`audit`), hệ thống tự động tạo ra hai thư mục tạm thời độc lập trên ổ cứng:
  - **Thư mục Mẫu Vi Phạm (`Fail Fixture`)**: Tạo các file cấu hình thiếu trường bắt buộc hoặc vượt quá trần 200 dòng, sau đó chạy bộ lọc và bắt buộc bộ lọc phải dừng lại với `exit code 1`.
  - **Thư mục Mẫu Đạt Chuẩn (`Pass Fixture`)**: Tạo đầy đủ các file đạt chuẩn, chạy lại chính bộ lọc đó và bắt buộc bộ lọc phải trả về `exit code 0`.
